## Принятые решения

- Astro 7.3.8, Node не ниже 22.12, TypeScript 6 (его требует `@astrojs/check`), `astro/tsconfigs/strict`.
- Адреса из spec §2 собираются из одной карты `ROUTES` в `src/i18n/routes.ts`. Языковой переключатель берёт ссылку оттуда же, поэтому ведёт на ту же страницу.
- `trailingSlash: 'always'` и `build.format: 'directory'`: адреса в spec без слеша (`/pt/sobre`) на хостинге открываются как `/pt/sobre/`.
- Все внутренние ссылки строятся через `withBase`/`pagePath`. Проверено сборками с пустым base и с `BASE_PATH=/elefante` (164 внутренние ссылки, ошибок нет). `npm run build` сам запускает проверку ссылок (`postbuild`).
- Workflow: `SITE_URL` по умолчанию `https://OWNER.github.io`, `BASE_PATH` по умолчанию `/REPO`. Если задана переменная репозитория `SITE_URL`, а `BASE_PATH` нет, base становится `/` (так переход на свой домен = «заменить SITE_URL, убрать BASE_PATH»). Версии действий взяты из официального README withastro/action: checkout@v7, withastro/action@v6, deploy-pages@v5.
- Язык запоминается кликом по переключателю PT/EN (`localStorage.lang`, в `try/catch`). Корень читает `lang`, затем `navigator.language` (en* → `/en/`, иначе `/pt/`).
- Пункт меню «Эпохи» ведёт на якорь `#epocas` главной (в spec нет общей страницы эпох). Выпадающий список эпох (`EpochNav`) будет позже.
- Чтобы пункт «Карта» не вёл в пустоту, добавлена заглушка `/pt/mapa/` и `/en/map/`. Самой карты нет, она в этапе 4.
- Тема только светлая. Переменные эпох (`--epoch-bg`, `--epoch-accent`, `--epoch-heading-font`, `--epoch-frame`) заданы значениями по умолчанию, настоящие стили эпох в этапе 6.
- Системные шрифты (sans для текста, serif для заголовков), иконки встроенным SVG, JavaScript только два маленьких inline-скрипта (выбор языка на корне, запоминание языка).

## Этап 4a: страница эпохи, лента, страницы нитей

Сделано по spec §5.2 и §5.5 на тестовых данных. Карты, клиентского фильтра, переключателя «Лента / Сетка», «Удиви меня» и главной нет (по условиям этапа).

- **Адреса:** `/pt/epoca/{slug}`, `/en/era/{slug}`, `/pt/fio/{slug}`, `/en/thread/{slug}`. Один файл `[lang]/[segment]/[slug].astro` отдаёт карточки, эпохи и нити (иначе три файла с одним шаблоном адреса столкнулись бы); тела страниц в `src/views/`. Эпоха получает страницу, если она `mvp: true` и в ней есть хотя бы одна карточка `ready`. Нить получает страницу только по `visibleThreads` (не меньше 5 карточек), скрытая нить страницы не имеет, а её чип на карточках остаётся обычным текстом.
- **Слаг у эпох и нитей:** поле `slug {pt, en}` добавлено в схему, данные, `check:data` (формат и уникальность внутри своего вида) и spec §7. Сейчас pt-слаг равен `id` (как перечислено в spec §2), английские слаги придуманы мной (`avis-and-the-discoveries`, `sea`, `food-and-wine` и т. д.) и помечены к подтверждению: после публикации слаг менять нельзя.
- **Страница эпохи:** заголовок, годы, фраза-тема, чипы нитей, лента, соседние эпохи. Лента это `<ol>` в хронологическом порядке: события каркаса крупнее, истории между ними мельче, сверху линия времени с точками. Запись это `EventCard` (год и место, название-ссылка, нити, метка, возраст, пометка «Tema difícil», миниатюра, крючок); слой «История» раскрывается на месте через `<details>` (работает без JS), внутри ссылка «Saber mais →» на страницу карточки.
- **Хэш в ленте:** открытая карточка пишет `#c-{id}` в адрес через `replaceState` (история не засоряется), ссылка с таким хэшем открывает карточку при загрузке. «Назад» из карточки возвращает на ту же позицию ленты вместе с раскрытой карточкой (проверено в браузере: 1897 → 1897).
- **Чипы нитей на странице эпохи:** обычные ссылки со счётчиком. Счётчик это число карточек нити **в этой эпохе** (основная или вторая нить), ссылка ведёт на страницу нити к секции этой эпохи (`/fio/mar/#e-{slug-эпохи}`), где ровно столько плиток. Чипы только для видимых нитей и только с ненулевым счётчиком; чипа «Все» нет, потому что фильтра нет. Для скринридера число читается словами («3 histórias»).
- **Страница нити:** название, описание, число историй, чипы эпох (якоря на секции, со счётчиками), секции по эпохам: заголовок-ссылка на страницу эпохи и сетка плиток `EventCard` (одна колонка на 360 px). Плитки без чипов нитей и без раскрытия, ведут на карточку.

## Заморозка слагов

**Правило.** Слаги эпох и нитей (`slug.pt`, `slug.en` в `epochs.yaml` и `threads.yaml`) замораживаются перед любым из трёх событий: первая публикация ссылок на сайт, печать QR-кодов, анонс проекта. Что наступит раньше, то и запускает заморозку. До этого слаги можно менять свободно; после этого слаг не меняется, потому что адрес уже напечатан или разослан. Если изменение всё же неизбежно, это отдельное решение владельца: на GitHub Pages нет серверных перенаправлений, поэтому старый адрес пришлось бы закрывать статической страницей-заглушкой. Тот же принцип относится к слагам карточек (`events`); таблицы для них нет, пока они тестовые.
