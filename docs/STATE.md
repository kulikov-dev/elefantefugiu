## Принятые решения

- Astro 7.3.8, Node не ниже 22.12, TypeScript 6 (его требует `@astrojs/check`), `astro/tsconfigs/strict`.
- Адреса из spec §2 собираются из одной карты `ROUTES` в `src/i18n/routes.ts`. Языковой переключатель берёт ссылку оттуда же, поэтому ведёт на ту же страницу.
- `trailingSlash: 'always'` и `build.format: 'directory'`: адреса в spec без слеша (`/pt/sobre`) на хостинге открываются как `/pt/sobre/`.
- Все внутренние ссылки строятся через `withBase`/`pagePath`. Проверено сборками с пустым base и с `BASE_PATH=/elefante` (164 внутренние ссылки, ошибок нет). `npm run build` сам запускает проверку ссылок (`postbuild`).
- Workflow: `SITE_URL` по умолчанию `https://OWNER.github.io`, `BASE_PATH` по умолчанию `/REPO`. Если задана переменная репозитория `SITE_URL`, а `BASE_PATH` нет, base становится `/` (так переход на свой домен = «заменить SITE_URL, убрать BASE_PATH»). Версии действий взяты из официального README withastro/action: checkout@v7, withastro/action@v6, deploy-pages@v5.
- Язык запоминается кликом по переключателю PT/EN (`localStorage.lang`, в `try/catch`). Корень читает `lang`, затем `navigator.language` (en* → `/en/`, иначе `/pt/`).
- Пункт меню «Эпохи» ведёт на якорь `#epocas` главной (в spec нет общей страницы эпох). Выпадающий список эпох (`EpochNav`) будет позже.
- Чтобы пункт «Карта» не вёл в пустоту, добавлена заглушка `/pt/mapa/` и `/en/map/`. Самой карты нет, она в этапе 4.
- Тема только светлая. Переменные эпох (`--epoch-bg`, `--epoch-accent`, `--epoch-heading-font`, `--epoch-frame`) заданы значениями по умолчанию, настоящие стили эпох в этапе 6.
- Системные шрифты (sans для текста, serif для заголовков), иконки встроенным SVG, JavaScript только два маленьких inline-скрипта (выбор языка на корне, запоминание языка).

## Решения владельца после этапа 1

- **Формат данных: YAML.** Один файл на событие в `src/content/events/`, тексты блочными строками (`|` и `>-`), комментарии допустимы. `epochs`, `threads`, `featured` тоже YAML. Проверено на Astro 7.3.8: `glob()` для `**/*.yaml` и `file()` для списка работают с `astro/loaders` и Zod из `astro/zod`; блочные строки и комментарии читаются, неверный тип поля роняет сборку. Отдельный YAML-пакет не нужен. Схемы и коллекции будут в этапе 2 (`src/content.config.ts`).
- **Id записи** в коллекции событий берётся из имени файла, поэтому имя файла должно совпадать с `id` или `id` выводится из имени (решить в этапе 2).
- **Сообщения об ошибках проверки** должны называть файл, поле и язык. Стандартные ошибки Astro уже дают запись, файл и путь поля (`hook.pt` включает язык). Для правил длины текста и обязательных полей при `status: ready` в этапе 2 добавлю явные сообщения вида «events/<файл>.yaml, поле story, язык pt: 83 слова, допустимо 40-70».
- `pt.json` и `en.json` остаются как есть, в YAML не переносятся.
- В `LICENSE-CONTENT.md` добавлено: название, логотип и слон-маскот не покрываются MIT и CC BY-SA.
- Бургер-меню отложено. Страницы `/pt/mapa/` и `/en/map/` остаются заглушками.

Zod проверяет типы и обязательность, `check:data` добавляет правила: слова (hook до 12, story 40-70, more до 150, для `placeholder: true` только предупреждение), slug (латиница, цифры, дефисы; уникален отдельно для pt и en), нити только из справочника (1-2, первая основная), id = имя файла, frame = importance 3, `ready`: оба языка не пусты и не TODO, bridge заполнен, источники (2 для каркаса, 1 для истории, http/https), `reviewed_by`, `reviewed_on`; image: alt на обоих языках, license, файл есть в `public/`; координаты внутри материка, Мадейры или Азор; `related` и `featured` ссылаются на существующие события; featured ровно 3.

Без картинки: 07 и 16. Интерактивы: `army_dots` в 02, `ship_scale` в 03. Все годы, числа и координаты выдуманные или примерные.

## Этап 3: страница карточки

Сделано по spec §5.3 на тестовых данных, страница без карты.

- **Адреса:** один файл `[lang]/[segment]/[slug].astro` строит `/pt/historia/{slug}` и `/en/story/{slug}` из карты `STORY_SEGMENT` и slug каждого языка. Только события со статусом `ready`. Всего 48 страниц карточек (24 события x 2 языка).
- **Блоки:** хлебные крошки, заголовок с годом и местом, метки (нить, TagLabel, AgeBadge, HeavyTopicBanner для `sensitive`), иллюстрация (подпись `caption`, «автор · лицензия»), слой 1 крючок, слой 2 история, слой 3 «Подробнее» (контекст, интерактив-заглушка, «Мост в сегодня», источники, дата проверки), «Ещё рядом», «Поделиться» и «Нашли ошибку?», предыдущая и следующая карточка в эпохе.
- **Слой 3** это `<details id="detalhes">`, работает без JS. Слой 2 (`#historia`) на странице карточки всегда раскрыт; `#historia` служит якорем. Скрипт в `CardLayers`: `#detalhes` при загрузке раскрывает слой, переключение обновляет адрес через `replaceState` (история браузера не засоряется), `#historia` слой закрывает, при закрытии `#detalhes` убирается.
- **Поделиться:** без JS обычная ссылка на карточку; с JS ссылка заменяется кнопкой: Web Share API, иначе копирование текущего адреса (вместе с `#detalhes`) и подтверждение в `role="status"`; отказ браузера копировать показывает ссылку текстом; закрытие диалога молчит. Устаревший `execCommand` не используется.
- **Метатеги:** `title` (название события · сайт), `description` (первое предложение истории, до 200 знаков, учитывает сокращения вроде «D.», «séc.»), `canonical`, hreflang pt, en, x-default с реальными slug каждого языка, Open Graph и Twitter. `og:title` это крючок (spec §5.3). Для карточек с `sensitive` в превью всегда запасная картинка эпохи, не своя.
- **«Ещё рядом»:** связи `related` по порядку данных, затем ближайшие по расстоянию (при равенстве сначала та же эпоха), до 7, только `ready`. Параметр `allowed` оставлен для семейного режима (этап 5).
- **Подпись к иллюстрации:** необязательное `image.caption {pt, en}` (схема, spec §7, `check:data`, шаблон). Подпись видна, «автор · лицензия» показываются всегда. Если `caption` задана, нужны оба языка.
- **Запасная картинка эпохи:** необязательное `fallback_image` у эпох (путь внутри `public/`, `check:data` проверяет, что файл есть).
- **Тексты рыбы:** содержимое карточек с `placeholder: true` отмечено `lang="la"` (латинская заглушка), чтобы скринридеры не читали её как португальский. Заметная пометка «Texto de teste» / «Test text» над заголовком.
- **Тестовые данные изменены:** у события 06 диапазон лет `1519-1522`, у 08 есть `year_label`, у 02 есть `caption`.
- **Сборка:** `npm run build` = проверка ключей, `npm test`, `check:data`, сборка Astro, затем `postbuild`: ссылки, карточки, вес.

## Открытые вопросы

- **Форма «Нашли ошибку?»:** страницы `/pt/corrigir/` и `/en/report/` пока заглушки. Ссылка из карточки уже передаёт адрес: `?url=<полный адрес карточки>`. Нужно решить, куда уходят сообщения на статическом сайте (например GitHub Issues с шаблоном или внешняя форма), и не нарушить правило «без сторонних трекеров».
- **Растровые превью 1200x630 (этап 8):** Open Graph и Twitter не принимают SVG, а все картинки сейчас SVG-заглушки. Для настоящих превью нужны PNG или JPG 1200x630 для карточек и запасные по эпохам; способ получения (вручную или генерация при сборке) решить на этапе 8. Пока `og:image` указывает на SVG.
- **`noindex` у рыбы:** держится до `placeholder: false`. Перед запуском поставить `ALLOW_PLACEHOLDER=false`, тогда сборка упадёт, пока остаются такие записи.
- Правообладатель в `LICENSE`: сейчас «O Elefante Fugiu contributors», 2026. Подтвердить.
- `/p/{slug}` на GitHub Pages: серверных перенаправлений нет, нужно решение для этапа 7 (spec §12, п. 4).
- Версия Node в workflow не закреплена (см. «Версии»).
