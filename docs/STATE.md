## Принятые решения

- Astro 7.3.8, Node не ниже 22.12, TypeScript 6 (его требует `@astrojs/check`), `astro/tsconfigs/strict`.
- Адреса из spec §2 собираются из одной карты `ROUTES` в `src/i18n/routes.ts`. Языковой переключатель берёт ссылку оттуда же, поэтому ведёт на ту же страницу.
- `trailingSlash: 'always'` и `build.format: 'directory'`: адреса в spec без слеша (`/pt/sobre`) на хостинге открываются как `/pt/sobre/`.
- Все внутренние ссылки строятся через `withBase`/`pagePath`. Проверено сборками с пустым base и с `BASE_PATH=/elefante` (164 внутренние ссылки, ошибок нет). `npm run build` сам запускает проверку ссылок (`postbuild`).
- Workflow: `SITE_URL` по умолчанию `https://OWNER.github.io`, `BASE_PATH` по умолчанию `/REPO`. Если задана переменная репозитория `SITE_URL`, а `BASE_PATH` нет, base становится `/` (так переход на свой домен = «заменить SITE_URL, убрать BASE_PATH»). Версии действий взяты из официального README withastro/action: checkout@v7, withastro/action@v6, deploy-pages@v5.
- Язык запоминается кликом по переключателю PT/EN (`localStorage.lang`, в `try/catch`). Корень читает `lang`, затем `navigator.language` (en* → `/en/`, иначе `/pt/`).
- Пункт меню «Эпохи» ведёт на якорь `#epocas` главной (в spec нет общей страницы эпох). Выпадающий список эпох (`EpochNav`) будет позже.
- Чтобы пункт «Карта» не вёл в пустоту, добавлена заглушка `/pt/mapa/` и `/en/map/`. Самой карты нет, она в этапе 4.
- Тема только светлая. Переменные эпох (`--epoch-bg`, `--epoch-accent`, `--epoch-heading-font`, `--epoch-frame`) заданы значениями по умолчанию, настоящие стили эпох в этапе 6.
- Системные шрифты (sans для текста, serif для заголовков), иконки встроенным SVG, JavaScript только два маленьких inline-скрипта (выбор языка на корне, запоминание языка).

## Решения владельца после этапа 1

- **Формат данных: YAML.** Один файл на событие в `src/content/events/`, тексты блочными строками (`|` и `>-`), комментарии допустимы. `epochs`, `threads`, `featured` тоже YAML. Проверено на Astro 7.3.8: `glob()` для `**/*.yaml` и `file()` для списка работают с `astro/loaders` и Zod из `astro/zod`; блочные строки и комментарии читаются, неверный тип поля роняет сборку. Отдельный YAML-пакет не нужен. Схемы и коллекции будут в этапе 2 (`src/content.config.ts`).

Для правил длины текста и обязательных полей при `status: ready` в этапе 2 добавлю явные сообщения вида «events/<файл>.yaml, поле story, язык pt: 83 слова, допустимо 40-70».
- `pt.json` и `en.json` остаются как есть, в YAML не переносятся.
- В `LICENSE-CONTENT.md` добавлено: название, логотип и слон-маскот не покрываются MIT и CC BY-SA.
- Бургер-меню отложено. Страницы `/pt/mapa/` и `/en/map/` остаются заглушками.

## Этап 3: страница карточки

Сделано по spec §5.3 на тестовых данных, страница без карты.

- **Адреса:** один файл `[lang]/[segment]/[slug].astro` строит `/pt/historia/{slug}` и `/en/story/{slug}` из карты `STORY_SEGMENT` и slug каждого языка. Только события со статусом `ready`. Всего 48 страниц карточек (24 события x 2 языка).
- **Блоки:** хлебные крошки, заголовок с годом и местом, метки (нить, TagLabel, AgeBadge, HeavyTopicBanner для `sensitive`), иллюстрация (подпись `caption`, «автор · лицензия»), слой 1 крючок, слой 2 история, слой 3 «Подробнее» (контекст, интерактив ArmyDots или ShipScale, «Мост в сегодня», источники, дата проверки), «Ещё рядом», «Поделиться» и «Нашли ошибку?», предыдущая и следующая карточка в эпохе.
- **Слой 3** это `<details id="detalhes">`, работает без JS. Слой 2 (`#historia`) на странице карточки всегда раскрыт; `#historia` служит якорем. Скрипт в `CardLayers`: `#detalhes` при загрузке раскрывает слой, переключение обновляет адрес через `replaceState` (история браузера не засоряется), `#historia` слой закрывает, при закрытии `#detalhes` убирается.
- **Поделиться:** без JS обычная ссылка на карточку; с JS ссылка заменяется кнопкой: Web Share API, иначе копирование текущего адреса (вместе с `#detalhes`) и подтверждение в `role="status"`; отказ браузера копировать показывает ссылку текстом; закрытие диалога молчит. Устаревший `execCommand` не используется.
- **Метатеги:** `title` (название события · сайт), `description` (первое предложение истории, до 200 знаков, учитывает сокращения вроде «D.», «séc.»), `canonical`, hreflang pt, en, x-default с реальными slug каждого языка, Open Graph и Twitter. `og:title` это крючок (spec §5.3). Для карточек с `sensitive` в превью всегда запасная картинка эпохи, не своя.
- **«Ещё рядом»:** связи `related` по порядку данных, затем ближайшие по расстоянию (при равенстве сначала та же эпоха), до 7, только `ready`. Параметр `allowed` оставлен для семейного режима (этап 5).
- **Подпись к иллюстрации:** необязательное `image.caption {pt, en}` (схема, spec §7, `check:data`, шаблон). Подпись видна, «автор · лицензия» показываются всегда. Если `caption` задана, нужны оба языка.
- **Запасная картинка эпохи:** необязательное `fallback_image` у эпох (путь внутри `public/`, `check:data` проверяет, что файл есть).

- **Тестовые данные изменены:** у события 06 диапазон лет `1519-1522`, у 08 есть `year_label`, у 02 есть `caption`.
- **Сборка:** `npm run build` = проверка ключей, `npm test`, `check:data`, сборка Astro, затем `postbuild`: ссылки, карточки, вес.

## Этап 4a: страница эпохи, лента, страницы нитей

Сделано по spec §5.2 и §5.5 на тестовых данных. Карты, клиентского фильтра, переключателя «Лента / Сетка», «Удиви меня» и главной нет (по условиям этапа).

- **Адреса:** `/pt/epoca/{slug}`, `/en/era/{slug}`, `/pt/fio/{slug}`, `/en/thread/{slug}`. Один файл `[lang]/[segment]/[slug].astro` отдаёт карточки, эпохи и нити (иначе три файла с одним шаблоном адреса столкнулись бы); тела страниц в `src/views/`. Эпоха получает страницу, если она `mvp: true` и в ней есть хотя бы одна карточка `ready`. Нить получает страницу только по `visibleThreads` (не меньше 5 карточек), скрытая нить страницы не имеет, а её чип на карточках остаётся обычным текстом.
- **Слаг у эпох и нитей:** поле `slug {pt, en}` добавлено в схему, данные, `check:data` (формат и уникальность внутри своего вида) и spec §7. Сейчас pt-слаг равен `id` (как перечислено в spec §2), английские слаги придуманы мной (`avis-and-the-discoveries`, `sea`, `food-and-wine` и т. д.) и помечены к подтверждению: после публикации слаг менять нельзя.
- **Страница эпохи:** заголовок, годы, фраза-тема, чипы нитей, лента, соседние эпохи. Лента это `<ol>` в хронологическом порядке: события каркаса крупнее, истории между ними мельче, сверху линия времени с точками. Запись это `EventCard` (год и место, название-ссылка, нити, метка, возраст, пометка «Tema difícil», миниатюра, крючок); слой «История» раскрывается на месте через `<details>` (работает без JS), внутри ссылка «Saber mais →» на страницу карточки.
- **Хэш в ленте:** открытая карточка пишет `#c-{id}` в адрес через `replaceState` (история не засоряется), ссылка с таким хэшем открывает карточку при загрузке. «Назад» из карточки возвращает на ту же позицию ленты вместе с раскрытой карточкой (проверено в браузере: 1897 → 1897).
- **Чипы нитей на странице эпохи:** обычные ссылки со счётчиком. Счётчик это число карточек нити **в этой эпохе** (основная или вторая нить), ссылка ведёт на страницу нити к секции этой эпохи (`/fio/mar/#e-{slug-эпохи}`), где ровно столько плиток. Чипы только для видимых нитей и только с ненулевым счётчиком; чипа «Все» нет, потому что фильтра нет. Для скринридера число читается словами («3 histórias»).
- **Страница нити:** название, описание, число историй, чипы эпох (якоря на секции, со счётчиками), секции по эпохам: заголовок-ссылка на страницу эпохи и сетка плиток `EventCard` (одна колонка на 360 px). Плитки без чипов нитей и без раскрытия, ведут на карточку.
- **Соседние эпохи:** ближайшие по `order` в `epochs.yaml`. Ссылка, если у соседа есть страница; иначе обычный текст с названием и «Em breve» (не фокусируется). Логика покрыта тестом; в реальных данных теперь появляется (см. решения после этапа 4a).
- **ThreadChip и epochHref:** выполнено решение владельца. Крошка эпохи на карточке и чипы нитей (где у нити есть страница) ведут на настоящие страницы. Старый `#epocas` из `epochHref` удалён.
- **noindex:** остаётся и теперь стоит также на страницах эпох и нитей, если у них или у показанных карточек `placeholder: true`; снимается автоматически.
- **Новое правило данных:** опубликованная карточка в эпохе с `mvp: false` теперь ошибка `check:data` (у неё не было бы ни ленты, ни страницы эпохи).
- **Строки:** только в `pt.json` и `en.json` (ключи `epoch.*`, `thread.*`, `feed.*`, `plural.*`); число слов («1 história» / «n histórias») через `plural()` с `Intl.PluralRules` (pt-PT).
- **Не применено:** стили эпох из данных (`style.*`) пока не подключены к страницам, это этап 6; карточки используют общие переменные.

### Что сделано (коммит после каждого пункта, плюс кнопка карты отдельным коммитом)

Неизвестный `min_age` считается строжайшим (16), неизвестный `sensitive` считается тяжёлой темой, неизвестное сохранённое значение режима даёт off. Режим в `localStorage` (ключ `family`, всё в try/catch), при пустом, заблокированном или мусорном хранилище off. Встроенный скрипт в `<head>` (`src/lib/head-script.ts`, до таблиц стилей) ставит на `<html>`: `data-js`, `data-family`, `data-vista` (только `grelha`), `data-fio` (только известные нити; список нитей подставляется при сборке). Всё, что зависит от режима и не скрывается поэлементно, лежит в разметке вариантами `<span|div class="fv" data-modes="off all 12">`: по одному блоку на каждый различающийся результат (счётчики чипов, плиток эпох, страниц нитей и секций; «Ещё рядом»; «Предыдущая/Следующая»). Содержимое карточки остаётся в HTML. «Предыдущая/Следующая» и «Ещё рядом» считаются для каждого режима, текущая карточка остаётся в списке соседей.

## Решения владельца после этапа 7b-1 (выполнены отдельными коммитами)

- **Запасные значения без `light-dark()`.** Предложение «объявить светлое значение обычным свойством перед каждым `light-dark()`» для пользовательских свойств (`--color-bg: ...`) не работает: значение пользовательского свойства не проверяется при разборе стилей, поэтому следующая строка с `light-dark()` перекрывает запасную даже в браузере, который функцию не знает (свойства `color`, `background` с одной строкой запасного значения работали бы, наши токены нет). ## Этап: форма ошибки, статичные страницы, «Продолжить», sitemap, QR

Проверено в этой среде: `astro check` (0 ошибок), `npm test`, Vitest (в том числе новый `tests/vitest/pages.spec.ts`), полная сборка со всеми проверками `postbuild`. Браузерные наборы (`scripts/qa`, в том числе новый `pages.mjs`) не запускались.

### Решения

- **Форма «Нашли ошибку»** (`/pt/corrigir/`, `/en/report/`, `/ru/oshibka/`). Статичный сайт не может сам отправлять почту, поэтому обычная HTML-форма отправляется через сервис **FormSubmit** (formsubmit.co) на `elefantefugiu@gmail.com`. Это единственный сторонний получатель данных; он назван на странице «Правовая информация» (раздел «Приватность») и под самой формой. Без JavaScript форма всё равно работает (обычный POST, сервис возвращает читателя на страницу с `#sent`); с JavaScript отправка идёт через `fetch`, подтверждение появляется на месте, при сбое показан адрес для письма напрямую. Поля: страница (подставляется из `?url=` только если это http(s)), «что неверно» (обязательное, от 5 знаков), «как правильно», источник, почта (по желанию), скрытая ловушка для роботов (`_honey`), язык. Страница закрыта `noindex`. Альтернатива `mailto:` отвергнута: у читателей с веб-почтой она не открывается. **Нужно сделать вам один раз после публикации:** отправить через форму тестовое сообщение и нажать «Activate» в письме от FormSubmit на `elefantefugiu@gmail.com` (письмо может попасть в «Спам»); пока адрес не подтверждён, сообщения не приходят.
- **Статичные страницы** (`/pt/sobre/`, `/pt/metodo/`, `/pt/legal/` и их `en`, `ru`): тексты в `src/data/static-pages.ts`, по три языка, одни и те же разделы (тест сверяет). «О проекте»: что это, для кого, «Foi aqui», на каком этапе, кто делает, как помочь, контакты. «Метод и источники»: метки достоверности, даты и источники, числа и оценки, возраст и тяжёлые темы (с семейным режимом), проверка, изображения (в том числе правило подписывать ИИ), исправления, языки. «Правовая информация»: лицензии (MIT, CC BY-SA 4.0, изображения, что не покрыто), приватность (что лежит в браузере: `lang`, `theme`, `family`, `lastEpoch`, `lastSurprise`; хостинг GitHub Pages; карта и тайлы; форма; внешние ссылки), предупреждение, контакты.
- **Что в статичных текстах должен подтвердить владелец** (я написал это по устройству проекта, но факты о людях знаете только вы): «независимый, бесплатный проект без рекламы»; «тексты пишет команда проекта» и «ищем рецензентов» (там призыв к специалистам); что три эпохи готовы; фраза о FormSubmit; что баннер о куки не нужен (в хранилище лежат только настройки, но spec §3.8 просит подтвердить у юриста). Португальский и русский тексты нужно вычитать носителем.
- **«Продолжить»** (spec §5.1): на странице эпохи и на карточке в `localStorage.lastEpoch` пишется id эпохи (он не зависит от языка); на главной скрытая кнопка «Продолжить: {эпоха}» показывается, если значение есть и эпоха имеет страницу. Заблокированное хранилище и чужое значение игнорируются.
- **Карта грузится всегда** на страницах с картой: код острова (около 46 КБ gzip) запрашивается сразу после загрузки страницы, а не при подходе блока к экрану. Рисуется карта (и грузятся тайлы), когда блок виден или в пределах одного экрана (на телефоне панель «Карта» скрыта, пока не выбрана, у скрытого блока нет размера, поэтому рисование ждёт её показа). Набор `map.mjs weight` обновлён.
- **F5 на карте оставлен как есть** (вид, то есть положение и масштаб, сохраняется в `history.state` и возвращается при перезагрузке). Лучшая практика: перезагрузка не должна терять то, что читатель сделал (браузеры так же возвращают прокрутку, а Google Maps держит позицию в адресе); состояние, которым делятся (`?fio`, `?epoca`, `?id`), и так в адресе; кнопка «Вся Португалия» возвращает общий вид. Если захотите иначе, это одна строка.
- **Node**: мажорная версия 22 закреплена в `.nvmrc`, в `setup-node` (`node-version-file`) и в `withastro/action` (`node-version: 22`); патчи 22.x подтягиваются сами (это LTS с security-исправлениями). В `package.json` остаётся `engines >= 22.12`.
- **sitemap.xml и robots.txt** (`scripts/make-sitemap.mjs`, первым шагом `postbuild`): строятся из готовых страниц, в карту попадают только страницы без `noindex` (сейчас это 9 страниц: «О проекте», «Метод», «Правовая информация» на трёх языках; остальные страницы с тестовым текстом закрыты `noindex` и появятся в карте сами, когда текст станет настоящим). В каждой записи `hreflang` самой страницы. **robots.txt работает только в корне домена**: на `github.io/REPO/` он лежит не там, где его ищут поисковики; полноценно заработает с собственным доменом (`SITE_URL`).

## `reviewed_by` / `reviewed_on` больше не нужны

- Оба поля необязательны (в схеме остались, чтобы не ломать черновики), `check-data` их не требует, на странице карточки ничего про «кто и когда проверил» не выводится (убран абзац «Проверено …» под источниками; `check-cards` следит, чтобы он не вернулся). - **Сборка с `ALLOW_PLACEHOLDER=false` теперь проходит** (0 ошибок, NOTE про `fallback_image` у Avis и Pombal).

## Пометка `placeholder` у эпох по полям

- У эпохи `placeholder` теперь список полей (`name`, `theme`, `style`, `intro`, `fallback_image`), пусто по умолчанию; у карточек и нитей остался `true/false`. Avis и Pombal: `[fallback_image]` (название, фраза и цвета утверждены); Estado Novo (страницы нет): `[theme, style, fallback_image]`; шесть остальных: `[]`. Страница эпохи `noindex` и «тестовая» только если помечено поле, кроме `fallback_image` (`epochHasTestText`): страницы Avis и Pombal теперь индексируются.
- Правило `ALLOW_PLACEHOLDER=false` (`check-data`): карточки `draft` не проверяются; эпохи без опубликованных историй не проверяются; пометка на `fallback_image` даёт `NOTE`; пометка на текстовом поле опубликованной карточки, эпохи с историями или нити с историями даёт ошибку. Описано в `docs/spec.md`, «Пометки-заглушки».
- Фразы `theme` оставлены (решение владельца).

## Браузерные наборы scripts/qa снова рабочие

Подробно (таблица наборов, запуск, фикстуры): `scripts/qa/README.md`. Коротко:

- **Запуск:** `npm run build`, затем `npm run qa` (все наборы и одна таблица, около 25 минут), `npm run qa -- <набор>` (один), `-- --list`, `-- --resume`, `-- --report`. Первый запуск сам ставит зависимости `scripts/qa`, поднимает статический сервер на `dist/` (порт 4400) и, где нужно, второй на сборке с фикстурами (порт 4401). На Windows и macOS берётся установленный Chrome или Edge (`CHROME_PATH` задаёт другой), на Linux `@sparticuz/chromium`. Раньше наборы не запускались на Windows (пути от `URL.pathname`, `/tmp`, Linux-браузер): теперь общий `browser.mjs`.
- **Данные не зашиты в наборы.** `data.mjs` читает `src/content` (те же файлы, что и сборка): опубликованные карточки (`status: ready`), готовые эпохи, нити, строки интерфейса, «за границей». Числа историй, названия эпох и нитей, адреса карточек берутся оттуда; набору, которому нужна карточка определённого вида (тяжёлая тема, 12+, интерактив), он выбирает её из данных и падает с понятным сообщением, если такой нет.
- **Фикстуры только в тестовой сборке.** У настоящих карточек нет 16+, эпохи длиннее 8 карточек (переключатель «Лента / Сетка» от 9), карточки с интерактивом «Размер нау», карточки без русского перевода, эпохи, которую режим оставляет пустой, и их меньше лимита маркеров (30), то есть нет кластеров и «Показать ещё». Для этого `prepare-variant.mjs` собирает **отдельную копию** сайта вне репозитория (`<tmp>/elefante-variant`) по плану `variant-plan.mjs`: восемь черновиков `evento-exemplo-17…24` (в репозитории `status: draft`) публикуются в копии; пять уходят в первую эпоху (в ней 10 карточек, есть тяжёлая тема), три остаются в Estado Novo и все 16+; одна несёт «Размер нау»; лимит маркеров в копии 7. Наборы с `-variant` в имени идут против неё.
- **Что изменилось по смыслу (не просто новые адреса):** меню «С детьми» вместо трёх сегментов (радиогруппа внутри раскрывающегося меню, выбор закрывает меню); «Удиви меня» теперь страница `/pt/surpreende-me/`, а не кнопка; мост на карточке: одна кнопка «Как добраться» и две текстовые ссылки (карта, сайт); ссылка «Заметили неточность» под «Поделиться»; карточки ленты одинаковые и без полосы азулежу; активная карточка отмечена тенью, а не контуром; карта на странице эпохи грузит код сразу (плитки только когда панель видна); лимит маркеров 30; переключатель вида только от 9 историй; слон на 404 теперь `think`, не `sad`.
- **Найдено тестами и исправлено:** короткая эпоха (меньше 9 историй) при `?vista=grelha` на мгновение рисовала сетку и потом перескакивала в ленту (сдвиг макета 0,11 по CLS). Теперь короткий встроенный скрипт в `EpochView.astro` снимает `data-vista` до того, как лента нарисована.
- **Найдено и не исправлено (за вами):** (1) в названиях источников на карточках стоят русские пометки редактора, например «(формулировка «possibly»)», «(о книге Бедини)»: они видны на страницах pt и en в списке источников и заставляют их грузить кириллические шрифты, когда список открыт; (2) описания нитей («Descrição de exemplo do fio Mar.») и три из эпох ещё `placeholder: true`: сейчас они на настоящих страницах (`ALLOW_PLACEHOLDER=false` остановит такую сборку).
- **Страница из черновиков не может попасть в продакшен:** `scripts/check-published.mjs` стоит в конце `postbuild` и падает, если в `dist/` есть страница, QR-страница, строка sitemap, точка на любой карте (`data-map-config`, `data-home-map-config`), id, slug, заголовок карточки, не опубликованной (не `ready` или `placeholder: true`), или слово `evento-exemplo`; число точек на карте страницы и на главной равно числу опубликованных карточек. Проверка срабатывает на сборке с фикстурами (`CHECK_DIST=<dir>`, 651 нарушение) и пробуется в `tests/published.test.ts` на стендовых сборках.

## Страница карты: «Рядом со мной», мир, маркеры, шкала эпох

## Слон-маскот

Источник: PNG/WebP владельца (с кремовым фоном) в `docs/mascot/originals/` (не публикуются, в `public/` их нет). Восемь поз: `walk`, `run`, `peek`, `map`, `bow`, `think`, `stay`, `sad`. Позы `sleep` нет (слон в загрузке не нужен).

### Что сделано

- **Фон убран** скриптом `scripts/make-mascot.mjs` (`node scripts/make-mascot.mjs`, запускается вручную, результат коммитится): заливка от границы картинки, поэтому кремовые брюки и рубашка внутри контура остались; края «распакованы» по тёмному контуру, чтобы на тёмной теме не было светлой каймы. Результат: `public/mascot/<поза>.webp`, прозрачный фон, высота 640 px, 40–55 КБ; плюс `head.webp` (обрезка головы из `stay`, 18 КБ) для логотипа.
- **Компонент** `src/components/Mascot.astro` (`pose`, `size`: `normal` | `small` | `logo`, `enter`), логика в `src/lib/mascot.ts` (`POSES`, `POSE_SIZE`, `mascotAllowed`). Картинка декоративная (`alt=""`), с `width` и `height`, `loading="lazy"` кроме логотипа. Стили: `src/styles/mascot.css`, токены `--size-mascot`, `--size-mascot-small`, `--mascot-shift`, `--mascot-halo` (в тёмной теме слабый светлый ореол вокруг тёмного контура, в светлой прозрачный).
- **Где слон есть:** логотип в шапке (голова, заменила SVG-заглушку); страница 404 (`sad`); пустая лента эпохи (`peek`) и пустой семейный режим на страницах эпохи и нити (`think`); на странице эпохи «идёт» (`walk`) по верхнему краю ссылки «Следующая эпоха» и появляется при прокрутке (`animation-timeline: view()`, браузеры без неё показывают слона на месте; только `transform` и `opacity`, один раз; при `prefers-reduced-motion` без движения).
- **Где слона нет:** на страницах карточек (все карточки: любая может оказаться тяжёлой, 16+ или про режим), на страницах эпохи Estado Novo (в том числе в пустых состояниях), в загрузке карты (там «дышащая плитка»). Один раз на экран. Поза `walk` не показывается, если следующая эпоха Estado Novo (поэтому сейчас слон идёт только на странице Avis; на странице Pombal следующая эпоха режимная).
- **Проверки:** `scripts/check-mascot.mjs` (в `postbuild`: картинка существует, пустой `alt`, размеры, не больше 3 картинок на странице кроме логотипа, нет на карточках и эпохе режима, логотип есть в шапке каждой страницы); `tests/vitest/mascot.spec.ts` (7 тестов: файлы есть, WebP с альфой, оригиналы не в `public/`, правила `mascotAllowed`); `check-cards` и `check-listings` не считают слона иллюстрацией; набор `scripts/qa/mascot.mjs` (логотип на 320/360/1280, 404, слон у пагинатора, пустые состояния, ореол в тёмной теме, без движения при `reduced-motion`).

### Решено мной

- Слона **нет на карточках вообще**, а не «нет на тяжёлых»: проще проверить, и ни одна карточка не рискует получить его случайно. Если хотите слона на мирных карточках (например, «пустой» или поклон в конце), это `mascotAllowed` и одна строка в `StoryView`.
- Логотип теперь картинка (голова слона) вместо одноцветной SVG: она не меняет цвет по эпохам. Голова шире прежнего знака: при 320 px шапка может стать тесной, проверяет `qa mascot logo`.
- Позы `map`, `bow`, `stay` лежат готовыми и пока не использованы.

### Не проверено

Браузерные наборы не запускались, как выглядят слон и шапка на экране не смотрел (только картинки на тёмном фоне и сборку). Права на образ нужно оформить письменно с иллюстратором (см. `docs/design.md` §5).

## Этап RU: русский язык как третий язык (инфраструктура)

### Решения

- **Как запасной язык попадает на страницы.** Все локализованные поля данных теперь `{pt, en, ru?}`. Загрузчик (`loadSite`) один раз вызывает `localize` (`src/lib/localize.ts`): в каждом текстовом объекте появляется `ru`, это русский текст у события с `ru_ready: true`, иначе английский (при пустом английском португальский). Страницы читают `x[lang]` как раньше. Тип данных `Localized<...>` гарантирует `ru: string`, поэтому TypeScript нашёл все места, где знали только два языка.
- **`ru_ready`** (по умолчанию `false`) у события. `true` без русского текста в любом локализованном поле (или без русского слага) роняет схему Zod (`superRefine` в `src/data/schemas.ts`) с путём вида `story.ru`; `check:data` проверяет длины (hook до 12, story 40-70, more до 150, `bridge.note` до 20 слов и одно предложение), alt и подписи картинки, тексты интерактивов для русского тоже, у заглушек предупреждения.
- **Русская страница карточки без перевода** (`ru_ready: false`): адрес по английскому слагу (`/ru/istoriya/{английский слаг}/`), английский текст с `lang="en"` (для латинской рыбы `la`), плашка `card.not_translated` («Эта страница пока не переведена. Показан текст на английском.»), `noindex`, ни одной ссылки `hreflang`. Страницы `pt` и `en` такой карточки называют только `pt`, `en` и `x-default` (и `og:locale:alternate` без `ru_RU`). Для карточки с `ru_ready: true`: `pt`, `en`, `ru`, `x-default`. Остальные страницы (главная, эпохи, нити, статичные, карта) считаются готовыми на русском: у них русский интерфейс и русские названия.
- **Корень `/`:** `localStorage.lang`, затем `navigator.language` (`ru*` -> `/ru/`, `en*` -> `/en/`, иначе `/pt/`); чистая функция `chooseLang` и встроенный скрипт `rootScript` (`src/lib/lang-choice.ts`), Vitest гоняет скрипт во всех сочетаниях и сверяет с функцией. Без JavaScript на корне три ссылки (Português, English, Русский).
- **Переключатель языка: выпадающий список `<details>`, а не три сегмента.** Расчёт: логотип с названием (около 205 px) и три сегмента по 44 px (около 135 px) не помещаются в 288 px (320 px минус поля), а на 360 px (328 px) не хватает около 12 px. Кнопка с текущим языком (`PT ▾`, 44 px высотой) раскрывает список из трёх названий (Português, English, Русский) по 44 px. Высота шапки не меняется (та же строка, что была): цель из задания (не больше 145 px на 320 и 360 px) проверяет `scripts/qa/ru.mjs menu`, но я его не запускал. Список закрывается Escape (фокус возвращается на кнопку), щелчком в сторону и уходом фокуса; ссылки по-прежнему переносят `?fio`, `?vista`, `?epoca`, `?id`.
- **Множественное число.** У русского четыре формы (`one`, `few`, `many`, `other`). `plural()` берёт `_one|_few|_many|_other` по `Intl.PluralRules` и падает на `_other`; в `ru.json` у `plural.stories`, `map.cluster` и `map.in_area` есть все четыре формы, а `check:i18n` разрешает `_few` и `_many` только русскому. Скрипты в браузере (остров карты, фильтр ленты) выбирают форму той же функцией (`src/lib/plural-pick.ts`) по `Intl.PluralRules` локали страницы; Vitest сверяет выбор в браузере с серверным для 12 чисел и трёх языков.
- **Шрифты.** У Playfair Display (вариативный), Source Serif 4 (400, 400 курсив, 600) и Oswald (600) в Fontsource есть кириллические подмножества во всех нужных начертаниях, замен не нужно. Объявлены теми же семействами с `unicode-range` кириллицы, preload нет: браузер скачивает файл, только если страница рисует кириллическую букву (закрытый список языков её не рисует). Вес на странице `/ru/`: Playfair 21,1 КБ, Source Serif 14,2 + 13,7 + 14,8 КБ, Oswald 6,8 КБ, всего до 70,6 КБ (вместе с латиницей ~110 КБ). Страница 404 рисует все три языка, поэтому качает их тоже. Запасные лица для кириллицы (`scripts/font-fallbacks-cyrillic.mjs`): Source Serif 4 `size-adjust` 119,93%, Playfair 113,35%, Oswald 88,63%. Подробности в `docs/visual-direction.md` §5.
- **Цифры и даты:** `LOCALES` (`pt-PT`, `en-GB`, `ru-RU`) в `routes.ts`, оттуда числа (`formatNumber`), даты (`formatDate`), `og:locale` (`ru_RU`).

## Открытые вопросы

- ~~Английские слаги эпох и нитей~~ **Согласованы владельцем** вместе с русскими и со статичными адресами (таблица в `docs/addresses.md`). Слаги заморожены: менять их можно только с перенаправлением со старого адреса.
- **Форма «Нашли ошибку?»:** страницы `/pt/corrigir/` и `/en/report/` пока заглушки. Ссылка из карточки уже передаёт адрес: `?url=<полный адрес карточки>`. Нужно решить, куда уходят сообщения на статическом сайте (например GitHub Issues с шаблоном или внешняя форма), и не нарушить правило «без сторонних трекеров».
- **Растровые превью 1200x630 (этап 8):** Open Graph и Twitter не принимают SVG, а все картинки сейчас SVG-заглушки. Для настоящих превью нужны PNG или JPG 1200x630 для карточек и запасные по эпохам; способ получения (вручную или генерация при сборке) решить на этапе 8. Пока `og:image` указывает на SVG.
- **`noindex` у рыбы:** держится до `placeholder: false`. Перед запуском поставить `ALLOW_PLACEHOLDER=false`, тогда сборка упадёт, пока остаются такие записи.
- Правообладатель в `LICENSE`: сейчас «O Elefante Fugiu contributors», 2026. Подтвердить.
- `/p/{slug}` на GitHub Pages: серверных перенаправлений нет, нужно решение для этапа 7 (spec §12, п. 4).
- Версия Node в workflow не закреплена (см. «Версии»).
- **Источник тайлов (spec §5.4, ⚠):** публичный сервер OpenStreetMap не рассчитан на постоянную нагрузку. Нужен провайдер с бесплатным тарифом или собственные тайлы; решить до публичного запуска, затем задать переменные репозитория `TILE_URL` и `TILE_ATTRIBUTION` (workflow их передаёт). Выбор провайдера влияет и на приватность (запросы тайлов идут с адресов читателей к стороннему серверу): это нужно отразить на странице «Informação legal» и в подвале.
- **Тайлы карты светлые, в тёмной теме слепят (открытый вопрос).** Тайлы OpenStreetMap светлые, в тёмной теме карта выглядит яркой светлой плитой среди тёмной страницы; маркеры, подписи и атрибуция на ней в тёмной теме по контрасту не мерились. Решается при выборе провайдера тайлов (см. «Источник тайлов»): нужен провайдер или собственные тайлы с тёмным стилем и возможностью переключать стиль по теме (`data-theme` уже есть, `TILE_URL` задаётся при сборке и должен стать парой светлый/тёмный). До выбора допустимы временные меры, но не делались: затемнить тайлы CSS-фильтром (искажает цвета и атрибуцию) или оставить светлую карту.
- **Перезагрузка карты возвращает последний вид** (положение и масштаб в `history.state`). Это нужно для «Назад», но F5 тоже возвращает его; если нужно иначе (F5 всегда с целой страны), скажите.
- **Загрузка карты на страницах эпох:** остров (46 КБ gzip) грузится, когда блок карты попал в зону видимости (на десктопе сразу, на телефоне при открытии панели «Mapa»). Если на мобильном трафике это дорого, можно загружать по нажатию кнопки «Показать карту».

- **Проверки:** `check-data` (файл, alt и подпись на всех языках истории, автор, лицензия из списка, `license_url` для BY и BY-SA, `source_url` кроме ИИ, `ai` и `AI-generated` вместе; предупреждение на слова «image/picture/изображение/картинка» в alt), `check-cards` (фигуры, подписи, автор, лицензия, ссылки, порядок «после текста до источников», `width`/`height`/`srcset`, `lazy`/`eager`). `ALLOW_PLACEHOLDER=false`: 0 ошибок, 0 предупреждений; `placeholder` с `fallback_image` у Avis и Pombal снят.
- **Идея на потом:** на портрете Помбала (van Loo и Vernet, 1766) слева под памятником стоит слон. В alt не включено, владелец сначала сам посмотрит оригинал.
- **Открыто:** Teylers и Qalam (см. «Источники на замену») не связаны с этим; Open Graph для эпох без объекта-картинки (Estado Novo) остаётся SVG-заглушкой.
